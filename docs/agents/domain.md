# Domain documentation

The repository has a single domain context.

Before domain or architecture work, read root `GLOSSARY.md` when present and
applicable decisions in `docs/adr/`. Use the glossary's terms consistently.
If these files do not exist, continue with the available documentation.

Create glossary entries when a domain term is agreed. Entries define domain
concepts rather than implementation details or task plans. Record an ADR when
a consequential trade-off is difficult to reverse and its rationale would
otherwise be surprising to a future maintainer.
