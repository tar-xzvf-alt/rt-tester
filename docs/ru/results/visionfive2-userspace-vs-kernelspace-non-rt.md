# VisionFive 2: пользовательское пространство и пространство ядра, без RT

[English](../../results/visionfive2-userspace-vs-kernelspace-non-rt.md)

Историческое сравнение v2. Исходный отчёт не указывает календарную дату запуска
или полные ревизии ядра без RT (реального времени)/обработчика/прошивки;
идентификаторы сеансов ниже сохраняют записанные сведения о происхождении.
Это не измерения из текущего учебного примера.

## Методика

Обе реализации измерялись с одинаковыми прошивкой Arduino Mega, проводкой,
ядром, привязкой к CPU (ядрам процессора), приоритетами и параметрами:

- 100 групп;
- 1500 запросов в группе;
- интервал запросов 1000 мкс;
- тайм-аут ответа 10000 мкс;
- пользовательский обработчик на CPU 1 с приоритетом FIFO 85;
- поток IRQ (аппаратного прерывания) GPIO (ввода/вывода общего назначения) на CPU 1 с FIFO 99;
- `node_exporter` на CPU 0 и 3 с `SCHED_OTHER`.

FIFO здесь — политика планирования реального времени `SCHED_FIFO`;
`SCHED_OTHER` — обычное планирование. Arduino допускает только один ожидающий
запрос. Тайм-аут ответа сохраняется как потерянный ответ и никогда не вызывает
повтор с новой меткой времени. Поэтому каждый корректный сеанс должен иметь
ровно 150000 запросов, 150000 ответов и ни одного тайм-аута для критерия приёмки
без потерь, использованного в этом сравнении. Сеансы с тайм-аутами остаются
диагностическими данными, но не удовлетворяют этому критерию.

Сеансы с нагрузкой использовали:

```text
stress-ng --cpu 4 --cpu-method int64 --vm 1 --vm-bytes 70% --vm-keep --timeout 0
```

Измерение начиналось только после прогрева 60 секунд и шести образцов
MemAvailable (доступной памяти) за 25 секунд. Наблюдаемый разброс памяти был ниже 0.11%.

## Сеансы без нагрузки

| Режим | Сеанс | Среднее хвоста, мкс | Средний джиттер, мкс | Средний максимум групп, мкс | Абсолютный максимум, мкс |
| --- | ---: | ---: | ---: | ---: | ---: |
| пользовательское пространство | 1785387676 | 304.83 | 83.91 | 364.68 | 696 |
| пространство ядра | 1785387677 | 228.62 | 63.53 | 277.00 | 480 |

На результат без нагрузки влияет регулятор частоты `schedutil`. Нагрузка CPU
поддерживает более высокую частоту целевой системы в нагруженных сеансах,
поэтому абсолютные значения без нагрузки и с ней нельзя сравнивать так,
будто частота была фиксирована.

с 150000 запросами, 150000 ответами и нулём тайм-аутов каждый.

## Артефакты

Исходные локальные пути — сведения о происхождении, а не поставляемые артефакты:

```text
~/.local/state/rt-tester/visionfive2-handler-comparison-v2/comparison.db
~/.local/state/rt-tester/visionfive2-handler-comparison-v2/idle-userspace-vs-kernelspace.png
~/.local/state/rt-tester/visionfive2-handler-comparison-v2/stressed-userspace-vs-kernelspace.png
~/.local/state/rt-tester/visionfive2-handler-comparison-v2/stressed-pair2.png
~/.local/state/rt-tester/visionfive2-handler-comparison-v2/stressed-pair3.png
```

Средние хвоста описывают сохранённые худшие образцы ответов (наибольшие задержки).
Средний джиттер — среднее стандартных отклонений всех полученных ответов групп;
указанное стандартное отклонение групп отличается от джиттера прошивки.
Исходный отчёт не полностью определяет процедуру агрегирования, поэтому
сохраняйте названия столбцов и значения, не переосмысляя их как статистику всей
совокупности. Неконтролируемое поведение частоты `schedutil` ограничивает
причинную интерпретацию различий без нагрузки/с нагрузкой. См.
[статистику](../reference/measurement-statistics.md) и
[методику сравнения](../methodology/gpio-measurements.md).
