# Измеритель Arduino

[English](../../hardware/arduino.md)

Arduino Mega 2560 отправляет переход сигнала запроса на **D7** и принимает ответ
целевой платы на **D20**. Он измеряет задержку (latency) между запросом и ответом
в микросекундах. В неё входят физический тракт GPIO (линий ввода-вывода общего
назначения) и обработка на целевой плате, а не только задержка пробуждения
планировщиком Linux. Прошивка находится в этом репозитории в `src/arduino-meter/`.

## Прошивка и электрическая подготовка

Откройте `src/arduino-meter/arduino-meter.ino` в Arduino IDE или настроенном
Arduino CLI. Установите Arduino AVR core и ArduinoJson, выберите Mega 2560
и фактический последовательный порт, затем соберите и загрузите прошивку.
Репозиторий не предоставляет автоматизированного скрипта сборки/загрузки.
Прошивка не входит в RPM инструментов ПК как устанавливаемая программа целевой
платы. Зафиксируйте ревизию прошивки и версии библиотек/инструментов.

GPIO Mega использует логику 5 В; GPIO VisionFive 2 — 3,3 В. Не подавайте запрос
5 В непосредственно на вход целевой платы. Используйте подходящее согласование
уровней с правильным направлением и убедитесь, что обратный сигнал удовлетворяет
порогам входа Arduino. Прошивка настраивает D20 как `INPUT_PULLUP`: учтите эту
подтяжку в электрической схеме, чтобы она не подавала опасное напряжение на выход
целевой платы. Соедините общую GND. Смещения линий устройств GPIO не являются
номерами физических контактов разъёма. Используйте
[полное руководство по подключению](../usage/standalone-gpio-walkthrough.md)
и проверьте техническую документацию платы и преобразователя уровней.

## Параметры измерения

| Параметр | Значение |
|---|---|
| `measurements_per_group` | Запросов в группе, 1–1500; по умолчанию 1500 |
| `worst_count` | Число сохраняемых наибольших задержек ответа; приёмник обычно выбирает 5% |
| `interval_us` | Минимальный интервал запросов; по умолчанию 300 мкс |
| `response_timeout_us` | Предельное время одного ответа, ограничиваемое прошивкой диапазоном 1–65535 мкс |
| `groups` | Число групп для автоматической остановки сеанса |

Arduino ждёт, пока истечёт минимальный интервал и предыдущий запрос получит ответ
либо завершится по тайм-ауту. Одновременно ожидается не более одного ответа.
Прерывание D20 `CHANGE` регистрирует ответ только при наличии ожидающего запроса.
Тайм-аут увеличивает счётчик; это не повтор с новой временной меткой и не отсчёт
задержки. Группы формируются по попыткам запросов, поэтому число полученных
отсчётов может быть меньше заданного размера группы.

Приёмник отправляет команды протокола через последовательный порт, например:

```text
START {"session_id":123,"groups":100,"worst_count":75,"interval_us":300,"measurements_per_group":1500,"response_timeout_us":10000}
STOP
```

Каждая завершённая группа выдаёт JSON. Конечный сеанс останавливается после
заданного числа групп. До подключения полного стенда проверьте обнаружение порта
и обработку команд подготовленной прошивкой. Во время измерения предоставьте
сценарию управление портом, сбросом и START; не открывайте одновременно другое
приложение последовательного порта.

## JSON группы

Иллюстративный корректный JSON с тремя сохранёнными отсчётами:

```json
{
  "session_id": 123456789,
  "group_index": 5,
  "timestamp": 12345678,
  "mean_latency_us": 250.0,
  "avg_latency_us": 479.67,
  "min_latency_us": 476,
  "max_latency_us": 487,
  "jitter_us": 12.34,
  "requests_sent": 1500,
  "responses_received": 1499,
  "timeouts": 1,
  "worst_count": 3,
  "worst_latencies_us": [487, 476, 476],
  "parameters": {
    "interval_us": 300,
    "measurements_per_group": 1500,
    "max_groups": 10,
    "response_timeout_us": 10000
  }
}
```

Пример иллюстрирует поля, а не зарегистрированное измерение. `timestamp` —
Arduino `millis()`. `mean_latency_us` — среднее по всем полученным ответам группы;
`avg_latency_us` и `min_latency_us` относятся к сохранённому хвосту наихудших
откликов; `max_latency_us` — наибольшая задержка полученного ответа. `jitter_us` —
стандартное отклонение совокупности относительно среднего всей группы, а не
стандартное отклонение хвоста или разность максимума и минимума. См.
[статистику](../reference/measurement-statistics.md) и
[хранение SQLite](../reference/sqlite-schema.md), чтобы понять, какие данные
сохраняются в базе.

При запусках с супервизором сценарий сбрасывает/останавливает Arduino до запуска
контроллера. После готовности он возобновляет приостановленный контроллер,
затем разрешает приёмнику START. Так переходы при сбросе/подготовке не попадают
в последовательность измерительной трассировки.
