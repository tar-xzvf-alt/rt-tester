# Приёмник на ПК

[English](../../usage/receiver.md)

Файл параметров приёмника — не профиль стенда: он не запускает GPIO-обработчик,
не загружает модуль ответа и не создаёт нагрузку. Здесь `target-stress` и
`target-payload` — записываемые метки, а не команды создания таких условий.
Жизненным циклом платы должен управлять сценарий выбранного режима. Локальный
`measurement.conf` также может содержать старый абсолютный путь базы и большое
число групп; проверяйте его, а не считайте переносимым примером быстрого запуска.

Приёмник управляет сеансами Arduino, получает JSON групп, запрашивает необязательные
метрики SoC (системы на кристалле) через Prometheus и сохраняет данные SQLite.
Сценарии запуска режимов обычно создают его конфигурацию и управляют жизненным
циклом; не запускайте другой приёмник на том же последовательном порту.
Для первого сбора используйте [автономную пошаговую процедуру](standalone-gpio-walkthrough.md).

RPM включает приёмник, импортёр и сводку трассировок. Построение графиков и
объединение остаются инструментами из исходного кода. Код находится в
`src/pc-receiver/`; см. [зависимости](../reference/dependencies.md),
[схему](../reference/sqlite-schema.md) и [анализ](analysis-and-reports.md).

## Конфигурация

Локальный `measurement.conf` из исходников не переносим без проверки `db` и
метаданных целевой системы. Выбор последовательного порта выполняется отдельно.
Важные параметры приёмника:

| Параметр | Значение | По умолчанию |
|---|---|---|
| `db` | Путь SQLite | `./arduino_data.db` |
| `measurements-per-group` | Запросы в группе, 1–1500 | `1500` |
| `measurement-interval-us` | Минимальный интервал запросов | `300` |
| `response-timeout-us` | Срок ожидания одного ответа Arduino | `10000` |
| `auto-stop-groups` | Число групп; ноль означает отсутствие ограничения | `2500` |
| `target-board`, `target-kernel` | Записываемые метки метаданных | `unknown` |
| `target-stress`, `target-payload` | Записываемые условия `on`/`off` (включено/выключено) | `off` |
| `prometheus-url` | Локальный API запросов (программный интерфейс) | Зависит от стенда |

Автоматические настройки используют номинальную длительность группы
`measurements-per-group * measurement-interval-us`:

```text
worst-count = max(1, integer 5% of measurements-per-group)
timeout-us = nominal group duration * 3
check-interval-us = nominal group duration
```

Явные `timeout-us` и `check-interval-us` переопределяют вычисленные значения.
Они контролируют пропавшие группы на ПК; `response-timeout-us` независимо
ограничивает один ожидающий запрос Arduino. Фактическая длительность группы
может превышать номинальную, если ответы занимают больше времени, чем интервал.

Arduino `mean_latency_us` — среднее **всех полученных ответов** группы;
`avg_latency_us` — среднее **сохраняемого худшего хвоста** (наибольших задержек),
а `min_latency_us` — минимум этого хвоста. `jitter_us` — стандартное отклонение
генеральной совокупности всех полученных ответов группы. Тайм-ауты — счётчики,
а не образцы задержки. SQLite не хранит поле среднего всей группы.
См. [статистику измерений](../reference/measurement-statistics.md).

## Интерактивный и автоматический сбор

```bash
rt-tester-receiver --params ./measurement.conf
```

Интерактивные команды: `start`, `stop` и `exit`; каждый `start` создаёт новый
сеанс. При прямом запуске приёмника используйте `--port /dev/ttyACM0` для явного
выбора порта и `--baud 115200` для скорости; иначе используются обнаружение
и скорость по умолчанию. Это параметры CLI (командной строки) приёмника, а не
поддерживаемые ключи конфигурации измерения. Автоматический сбор:

```bash
rt-tester-receiver --params ./measurement.conf \
  --groups 3 --start --exit-on-stop
```

Для сопоставления внешних трассировок добавьте явный `--session-id 123456`.
Приёмник предоставляет метрики на порту `9101`; метрики текущих значений Arduino
появляются после получения группы, поэтому пустой ответ метрик до сбора не
доказывает неисправность.

## Импорт трассировок

Для сеанса с супервизором, образцы трассировки которого сохранены в локальном Prometheus:

```bash
rt-tester-import-trace arduino_data.db 123456 \
  --prometheus-url http://localhost:9091
rt-tester-trace-summary arduino_data.db --session-id 123456
```

Импортёр заполняет `trace_group_metrics` по сеансу/группе/узлу/этапу. Сценарий
запуска стенда обычно выполняет импорт сам. Сохраняйте исходную базу SQLite:
инструмент объединения не копирует агрегаты трассировок.

## Целостность и состояние

Для каждой группы проверяйте `requests_sent = responses_received + timeout_count`,
непрерывность индексов, согласованность идентификаторов сеанса и фактическое
число сохранённых образцов задержки. При недостатке ответов хвост может быть
меньше запрошенного; без ответов образцов задержки нет. Отсутствующие исторические
счётчики означают неизвестность, а не подтверждение нулевых потерь.

Журналы приёмника и `metrics_all_groups.log` используют
`${XDG_STATE_HOME:-$HOME/.local/state}/rt-tester`. `RT_TESTER_STATE_DIR`
переопределяет этот каталог состояния приёмника, но не перемещает базу SQLite,
удалённые журналы или файлы мониторинга конкретного профиля.
См. [пути при выполнении](../reference/runtime-paths.md).
