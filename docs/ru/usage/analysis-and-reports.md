# Анализ и отчёты

[English](../../usage/analysis-and-reports.md)

Построение графиков и объединение баз выполняются из рабочей копии исходников;
они не включены в `rt-tester-tools`. Установите pandas, numpy и matplotlib,
как описано в [зависимостях](../reference/dependencies.md). Команды ниже выполняются
из `src/pc-receiver/` этой копии. Замените `DB` путём сохранённой базы, а `SESSION`
— фактическим идентификатором сеанса.

## Поиск и проверка сеанса

```bash
./plot_statistics.py DB --limit 250 sessions
./plot_statistics.py DB --limit 250 details SESSION
./plot_statistics.py DB validate --session SESSION
./plot_statistics.py DB latest --stress on
./plot_statistics.py DB latest --stress off
```

`--limit` — порог задержки в микросекундах; историческая методика использует `75`
без нагрузки и `250` с нагрузкой. Это не число строк и не срок ожидания ответа
Arduino. Отдельный глобальный параметр `--top` выбирает число сохранённых строк
худшего хвоста в каждой группе, включаемых в анализ задержки.

SQLite содержит сохраняемый худший хвост (наибольшие задержки), а не задержки
всех ответов. Средние, минимумы, процентили и максимумы графиков относятся к
выбранному сохранённому хвосту. Из них нельзя восстановить среднее всей группы
или её p95/p99 (95-й/99-й процентили). Сохранённый `jitter_us` — стандартное
отклонение всех полученных ответов, рассчитанное прошивкой. Различайте среднее
групповых джиттеров (разбросов задержки) и стандартное отклонение объединённой
совокупности. См. [статистику измерений](../reference/measurement-statistics.md).

Перед сравнением проверяйте непрерывность групп, учёт запросов/ответов/тайм-аутов,
события жизненного цикла и доступное сопоставление трассировок. В старых данных
могут отсутствовать счётчики или точные сведения о версиях; явно указывайте эти
пробелы. Успешная проверка валидатором не подтверждает правильность проводки и
не доказывает границу худшего случая.

## Графики и сравнение

```bash
./plot_statistics.py DB --session SESSION --limit 250 all
./plot_statistics.py DB --session SESSION --output latency.png latency+soc
./plot_statistics.py DB --session SESSION --output jitter.png jitter+soc
./plot_statistics.py DB trace --session SESSION --output trace.png
./plot_statistics.py DB events --session SESSION --output events.png
./plot_statistics.py DB compare SESSION_A SESSION_B --mode latency
./plot_statistics.py DB compare SESSION_A SESSION_B --mode jitter
./plot_statistics.py DB compare SESSION_A SESSION_B --mode overlay
./plot_statistics.py DB compare SESSION_A SESSION_B --normalize
```

Сравнивайте только совместимые плату, ядро, режим обработчика, прошивку, проводку,
нагрузку, размер группы, интервал, тайм-аут и размещение CPU/IRQ (ядер процессора
и обработчиков аппаратных прерываний). Нормализация помогает визуальному
сравнению, но убирает абсолютный масштаб задержки. Перед интерпретацией связи
задержки и нагрузки проверьте пропуски данных SoC (системы на кристалле).
См. [методику GPIO](../methodology/gpio-measurements.md).

## Полный отчёт

```bash
./plot_statistics.py DB report --session SESSION --limit 250 \
  --output-dir ./report/session_SESSION
```

При наличии данных отчёты содержат обзор, задержку/SoC, джиттер/SoC, трассировку,
события, сводку Markdown и указатель HTML. Сохраняйте входную базу и команду
анализа рядом с отчётом. [Автономная пошаговая процедура](standalone-gpio-walkthrough.md)
включает реальный исторический пример с происхождением и ограничениями метаданных,
а не выдуманные текущие результаты. Фактически выполненные проверки указаны в
[протоколе проверки](../reference/validation.md).

## Объединение баз

Из корня репозитория:

```bash
python3 src/pc-receiver/merge_databases.py tests merged.db
```

Для такого входного каталога инструмент просматривает только `tests/results_*/*.db`,
а не произвольные вложенные базы или `tests/old_databases/`. Он пересоздаёт выходную
базу, копирует группы с переназначенными внешними ключами задержек и совместимые
`soc_metrics` и `events`. Он **не** копирует `trace_group_metrics`, исходные файлы
трассировок или весь контекст эксперимента. Отсутствие старых столбцов может
привести к пропуску таблиц. Повторяющиеся ключи сеанса/группы могут объединить
группы разных источников; проверяйте уникальность сеансов и напечатанную сводку
источников. Используйте отдельный выходной путь и сохраняйте каждую исходную базу.
Объединённый каталог — удобство анализа, а не замена архиву.
