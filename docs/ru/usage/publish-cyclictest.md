# Публикация результатов cyclictest

[English](../../usage/publish-cyclictest.md)

Публикатор загружает проверенный комплект cyclictest (теста задержки пробуждения
планировщика) и вызывает `rt-results-import-cyclictest` внешнего сервера.
Он не записывает SQLite через сетевую файловую систему. Завершение измерения
не зависит от доступности сервера.

| Процесс | Вызов | Ошибка публикации |
|---|---|---|
| Только сбор | Сценарий запуска без `--publish` | Публикация не предпринимается |
| Сбор и публикация | Сценарий запуска с `--publish` | Предупреждение; измерение остаётся завершённым |
| Существующий комплект | Публикатор с путём/путями комплектов | Код выхода `1` |
| Очередь повторных попыток | Публикатор с `--pending` | Неудачные сопутствующие записи остаются ожидающими |

```bash
rt-tester-run-linux-benchmark --config ./cyclictest.conf \
  --duration 10m --publish
rt-tester-publish-cyclictest --config ./cyclictest.conf \
  ~/.local/state/rt-tester/cyclictest-results/RUN_UID
rt-tester-publish-cyclictest --config ./cyclictest.conf --pending
```

Можно передать несколько путей завершённых комплектов. Сопутствующие записи
находятся вне комплектов, поэтому повторные попытки не меняют неизменяемые
результаты. Состояния: `publishing` (публикуется), `pending` (ожидает) и
`published` (опубликовано); записи содержат путь комплекта, попытки, время
обновления и последнюю ошибку. `--pending` пропускает записи, каталоги комплектов
которых больше не существуют.

## Настройка своего сервера

```ini
[publish]
host = publisher@RESULTS_HOST
port = 22
identity = ~/.ssh/rt-results-publisher
remote-directory = /tmp/rt-tester-cyclictest-publish
importer = /usr/bin/rt-results-import-cyclictest
database = /var/lib/rt-results-prototype/cyclictest.db
state-directory = ~/.local/state/rt-tester/cyclictest-publish
```

Обязателен только `host`. Остальные значения по умолчанию показаны выше, кроме
`identity`: по умолчанию ключ выбирает SSH (протокол защищённого удалённого доступа).
Настройки SSH целевой системы и публикации независимы. ПК нужны Python 3, `ssh`,
`scp`, доступное для записи состояние и неинтерактивная аутентификация. Серверу
нужны Python 3, импортёр из `rt-results`, доступная для записи база каталога и
права создания/удаления временной области загрузки. Наличие репозитория и пакетов
для своего сервера установите отдельно. Используйте учётную запись с подходящими
правами импортёра/каталога; лабораторный доступ root не является переносимым
обязательным условием.

## Контракт проверки

До сетевого доступа публикатор проверяет версию схемы `1`, тип теста `cyclictest`,
статус `complete`, канонический UUID (универсальный уникальный идентификатор)
`run_uid`, объявленные `cyclictest.json`/`histogram.txt`, точное соответствие
объявленного набора файлов, ограничение путей пределами комплекта и размер/SHA256
(контрольную сумму) каждого файла. Эта схема комплекта независима от неиспользуемой
таблицы GPIO SQLite `schema_version`.

После загрузки серверный импортёр выполняет проверку повторно. Публикатор
подтверждает наличие `run_uid` в удалённой таблице `runs` и удаляет временную область.
Повторная загрузка того же комплекта не создаёт ещё один логический запуск.
Сохраняйте исходный комплект и сопутствующую запись при диагностике публикации.

Этот процесс публикует завершённые комплекты в каталог `rt-results`.
[Prometheus remote write](../observability/central.md) (удалённая запись метрик)
передаёт временные ряды GPIO/режима с супервизором в реальном времени и не
загружает их базы SQLite. Два механизма независимы.
