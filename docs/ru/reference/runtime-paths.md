# Пути файлов при выполнении

[English](../../reference/runtime-paths.md)

| Режим | Основной артефакт | Состояние на ПК | Состояние на целевой системе/сервере |
|---|---|---|---|
| Автономный GPIO (ввод/вывод общего назначения) | Настроенная база SQLite | Журналы приёмника, созданные конфигурации, состояние мониторинга | Журналы обработчика/нагрузки |
| С супервизором | SQLite, включая импортированные агрегаты трассировок | Состояние приёмника и мониторинга | Журналы среды исполнения/контроллера и исходные трассировки |
| Cyclictest | Завершённый комплект с UUID (уникальным идентификатором) | Сопутствующие записи публикации | Временная область загрузки, каталог `rt-results` |

## Собственные эксперименты GPIO

Нейтральные шаблоны используют пути-заготовки `.rt-tester-example`. До запуска
преобразуйте их в абсолютные пути по [шагу подготовки](../usage/standalone-gpio-walkthrough.md).
Храните отредактированные профили в постоянном каталоге эксперимента.

У относительных путей нет единого основания: пути, которыми управляет сценарий,
обычно отсчитываются от каталога его запуска, а относительный `[measurement] db`
приёмник разрешает из `src/pc-receiver/` в исходном или установленном дереве.
Сценарий затем ищет эту базу для сводки из собственного каталога. Поэтому база
может оказаться не там, где ожидается, либо сбор завершится ошибкой. Используйте
абсолютный `db` в профиле или абсолютный аргумент `--db`, а также абсолютные пути
мониторинга. Храните профили, версии, заметки о проводке и журналы вместе с базой;
для очистки используйте тот же адаптированный профиль.

Старые профили короткой проверки могут использовать `/tmp`; лабораторные профили
сравнения — конкретные домашние каталоги или каталоги состояния. Скопируйте их
и замените пути перед использованием. Не определяйте место результатов по имени
режима.

Журналы приёмника и `metrics_all_groups.log` обычно используют:

```text
${XDG_STATE_HOME:-$HOME/.local/state}/rt-tester
```

`RT_TESTER_STATE_DIR` переопределяет только этот каталог состояния приёмника.
Он не перемещает базу SQLite, журналы целевой системы, хранилище Prometheus,
файлы Grafana или файлы туннеля SSH (защищённого удалённого соединения), заданные
в профиле. Относительные пути целевой системы разрешаются удалённо; выбирайте
их независимо от путей на ПК.

SQLite — основной артефакт. Перед копированием работающей базы в режиме WAL
(журнала упреждающей записи) используйте резервное копирование SQLite либо
остановите записывающие процессы и обеспечьте согласованную копию; копирование
только `.db`, когда свежие записи находятся в WAL, может потерять данные.
Сохраняйте исходные базы режима с супервизором: инструмент объединения не
копирует `trace_group_metrics`.

## Комплекты cyclictest и публикация

Выберите собственный корневой каталог вывода, например:

```text
~/.local/state/rt-tester/cyclictest-results/<run_uid>/
~/.local/state/rt-tester/cyclictest-publish/<run_uid>.json
```

Сбор сначала использует скрытый каталог `.<run_uid>.partial`; после успешной
проверки записывается манифест и выполняется атомарное переименование в
`<run_uid>`. Неудачные/неполные каталоги не являются завершёнными результатами.
Сопутствующие записи публикации остаются вне завершённого комплекта.
Серверная область загрузки временная; каталог по умолчанию находится в
`/var/lib/rt-results-prototype/cyclictest.db`, путь настраивается через
`[publish] database`.

Передача метрик Prometheus через remote write (удалённую запись) не переносит
SQLite GPIO или исходные файлы трассировок. Публикация комплектов cyclictest —
отдельный [процесс публикации](../usage/publish-cyclictest.md).
См. [анализ](../usage/analysis-and-reports.md) для производных отчётов и
[мониторинг](../observability/central.md) для хранения метрик.
