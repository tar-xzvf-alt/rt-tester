# Статистика измерений и терминология

[English](../../reference/measurement-statistics.md)

## Что измеряет эксперимент GPIO

**GPIO** — ввод/вывод общего назначения. Arduino измеряет **задержку**:
время от своего перехода сигнала запроса до обнаруженного перехода ответа.
Автономная задержка включает GPIO, согласование электрических уровней,
обработку прерывания и обработчик в пользовательском пространстве.
Это не чистый тест планировщика.

**PREEMPT_RT** — конфигурация Linux с вытеснением для реального времени.
Записывайте фактическое ядро и конфигурацию; одна метка RT не устанавливает
верхнюю границу задержки.

**Сеанс** — один запуск измерений от START до остановки. **Группа** содержит
фиксированное число попыток запроса. **Сохраняемый худший хвост** — N наибольших
задержек полученных ответов в каждой группе, обычно 5% размера группы.
Тайм-ауты учитываются отдельно и не записываются как образцы задержки.

## Статистика всей группы и сохраняемого хвоста

Для R полученных ответов с задержками x среднее всей группы равно
`sum(x) / R`, а среднеквадратичный джиттер — `sqrt(sum((x - mean)^2) / R)`.
Джиттер здесь характеризует разброс задержек вокруг среднего.

| JSON прошивки / метрика в реальном времени | Совокупность и смысл | Представление в SQLite |
|---|---|---|
| `mean_latency_us` / `arduino_latency_mean` | Среднее **всех полученных ответов** одной группы | Отдельного столбца среднего всей группы нет |
| `avg_latency_us` / `arduino_latency_avg` | Среднее **сохраняемого худшего хвоста** | Вычисляется из строк `latencies` этой группы |
| `min_latency_us` / `arduino_latency_min` | Наименьшее значение хвоста, **не** минимум всей группы | Минимум сохранённых строк хвоста |
| `max_latency_us` / `arduino_latency_max` | Наибольшая задержка полученного ответа, входит в хвост | Максимум сохранённых строк хвоста |
| `jitter_us` / `arduino_jitter` | Стандартное отклонение генеральной совокупности **всех полученных ответов** относительно их среднего | `groups.jitter_us` |
| `worst_count` | Размер хвоста, сообщаемый прошивкой | `groups.worst_count` |
| `requests_sent`, `responses_received`, `timeouts` | Попытки запросов, ответы, истёкшие сроки ожидания ответа | Соответствующие счётчики, для `timeouts` — `timeout_count` |

Журналы JSON приёмника могут сохранять среднее всей группы. Каноническая схема
SQLite хранит отдельные значения хвоста и джиттер всей группы, а не каждый
отдельный ответ. Нельзя восстанавливать среднее или процентили всей группы из
хвоста. При одинаковом числе значений хвоста в группах среднее объединённого
хвоста равно среднему групповых средних хвоста. При неодинаковых количествах
эти статистики имеют разные веса.

Прошивка хранит задержки как 16-битные значения; интервалы от 65535 мкс и выше
ограничиваются значением 65535. На Mega время измеряется через `micros()`;
хранение микросекунд не означает разрешение прибора 1 мкс или откалиброванную
абсолютную точность.

## Процентили и пороги

`p95` или `p99` сохранённых строк хвоста — процентиль **сохраняемой совокупности**,
а не всех запросов. Процентиль — значение, ниже которого лежит заданная доля
выбранных данных. Отчёты должны указывать совокупность и отбор групп.
Наблюдаемый максимум не является доказанной границей худшего случая.
Пропавшие ответы нужно учитывать, даже если все сохранённые значения малы.

Параметр построителя графиков `--top` выбирает число худших сохранённых строк
для анализа **в каждой группе**; он не восстанавливает отброшенные ответы.
`--limit` — порог построения/анализа в микросекундах, а не срок ожидания ответа.
Исторические процедуры используют 75 мкс без нагрузки и 250 мкс с нагрузкой;
выберите и опишите осмысленный порог своего эксперимента, не считая эти значения
универсальными критериями успеха/неудачи.

Не путайте три независимые настройки времени:

| Настройка | Назначение |
|---|---|
| `measurement-interval-us` | Минимальный интервал перед новым запросом Arduino; ожидание ответа может его продлить |
| `response-timeout-us` | Срок ожидания одного ответа Arduino; прошивка ограничивает его диапазоном 1–65535 мкс |
| `timeout-us` приёмника | Тайм-аут обнаружения пропавших данных групп на ПК; обычно выводится из номинальной длительности группы |

Номинальная длительность группы равна `число запросов в группе × интервал`.
Ожидание ответов, передача по последовательному порту и обработка добавляют
время; интервал не гарантирует период выборки. При пропавших ответах группа
может занимать значительно больше времени.

## Целостность перед интерпретацией

Для текущей прошивки каждая завершённая группа должна удовлетворять условию
`requests_sent = responses_received + timeout_count`.
Эталонный запуск без потерь также требует всех запрошенных групп, непрерывных
индексов с нуля, нулевых тайм-аутов и ожидаемого числа сохранённых строк.
В старых базах счётчики могут отсутствовать: отмечайте учёт потерь как неизвестный,
а не выдумывайте результат без потерь.

Разделяйте результаты полного цикла GPIO и задержки пробуждения планировщика
cyclictest. Сравнивайте запуски только при известных проводке, прошивке, ядре,
обработчике, привязке/приоритетах, политике частот, нагрузке, интервале, сроке
ожидания и сохраняемой совокупности. См.
[пошаговую процедуру](../usage/standalone-gpio-walkthrough.md),
[методику GPIO](../methodology/gpio-measurements.md) и [схему](sqlite-schema.md).
