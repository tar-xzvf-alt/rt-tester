# Первые шаги

[English](../getting-started.md)

## 1. Выберите измеряемый тракт

| Режим | Измерение | Arduino | Установленная команда |
|---|---|---:|---|
| Автономный GPIO | Полный цикл запроса GPIO, обработки и ответа | Да | `rt-tester-run-gpio` |
| Raw Ethernet с супервизором | Полный цикл через контроллер, транспорт, супервизор и среду исполнения | Да | `rt-tester-run-stand` |
| Тест Linux | Задержка пробуждения планировщиком | Нет | `rt-tester-run-linux-benchmark` |

GPIO — линии ввода-вывода общего назначения. Arduino измеряет задержку (latency):
время между переходом сигнала запроса и переходом сигнала ответа. PREEMPT_RT —
конфигурация вытеснения Linux для работы в реальном времени; она не превращает
любой измеряемый тракт или наблюдаемый максимум в гарантированный срок ответа.

## 2. Подготовьте участников эксперимента

Управляющий ПК запускает инструменты и хранит основные артефакты. Целевым платам
нужны доступ по SSH, права на изменение политики планирования и привязки к CPU,
а также ПО выбранного режима. Для режимов GPIO дополнительно нужны Arduino с
прошивкой, правильное подключение, согласование логических уровней и общая земля.
Центральный сервер необязателен.

В ALT Linux, если настроенный репозиторий содержит пакет:

```bash
apt-get install rt-tester-tools
```

В [справочнике зависимостей](reference/dependencies.md) описаны установка локального
RPM, пакеты целевой платы и зависимости построения графиков. Автономный сценарий
требует работающий `node_exporter` на целевой плате даже при отключённом мониторинге.

## 3. Создайте собственную конфигурацию

Следуйте [автономному руководству](usage/standalone-gpio-walkthrough.md) для полной
подготовки. Скопируйте один из установленных примеров в каталог сохраняемого
эксперимента и отредактируйте копию:

```text
/usr/share/rt-tester-tools/configs/stands/examples/visionfive2-gpio-basic.conf
/usr/share/rt-tester-tools/configs/stands/examples/visionfive2-gpio-local.conf
/usr/share/rt-tester-tools/configs/stands/examples/visionfive2-gpio-central.conf
```

Замените `root@TARGET_HOST`, проверьте метки платы и ядра, конфигурацию GPIO,
доступ к последовательному порту Arduino, размер группы, интервал, тайм-аут ответа,
нагрузку и выходные пути. Для центрального режима также нужны ваши сервер, учётная
запись и ключ. Нейтральные примеры используют порты ПК `9101` (приёмник), `9092`
(Prometheus) и `3002` (Grafana или проброс центральной Grafana). Преобразуйте пути
примера `.rt-tester-example` в абсолютные на этапе подготовки из руководства:
приёмник запускается в другом рабочем каталоге, и неизменённый относительный путь
базы данных может разрешиться именно там.

## 4. Проверьте короткий запуск перед сбором серии

После подготовки оборудования и целевой платы:

```bash
rt-tester-run-gpio --config ./visionfive2-gpio-basic.conf \
  --groups 3 --no-prometheus --no-grafana
```

Базовый профиль требует обоих флагов отключения. Локальный и центральный профили —
отдельные сценарии, описанные в разделах [локального](observability/local.md) и
[централизованного мониторинга](observability/central.md). Для проверки панелей
используйте несколько групп: одна группа может завершиться до опроса метрик.

Для других подготовленных стендов:

```bash
rt-tester-run-stand --config ./supervised.conf \
  --groups 3 --no-prometheus --no-grafana
rt-tester-run-linux-benchmark --config ./cyclictest.conf --duration 10
```

`--dry-run` у сценариев GPIO не является проверкой только для чтения: он может
записывать сгенерированные конфигурации и проверять локальное состояние. Для
изучения синтаксиса командной строки используйте `--help`. `--prepare-only`
изменяет состояние целевой платы и не заменяет проверку.

## 5. Сохраните и проверьте результаты

Перед увеличением числа групп проверьте непрерывность их нумерации, учёт запросов,
ответов и тайм-аутов, события и метки. Данные GPIO находятся в настроенной базе
SQLite; cyclictest выводит путь завершённого комплекта результатов. Сохраните
конфигурации, журналы, версии и сведения о подключении вместе с основным артефактом.
Продолжите [анализ](usage/analysis-and-reports.md) и используйте соответствующую
методику [GPIO](methodology/gpio-measurements.md) или
[cyclictest](methodology/cyclictest-comparisons.md).

Для сборки из исходников и расширений используйте дополнительный
[маршрут разработчика](development/development-and-testing.md).
