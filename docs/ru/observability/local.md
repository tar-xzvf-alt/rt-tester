# Локальные Prometheus и Grafana

[English](../../observability/local.md)

Используйте этот сценарий после успешного выполнения
[базовой пошаговой процедуры GPIO](../usage/standalone-gpio-walkthrough.md).
GPIO — ввод/вывод общего назначения. Prometheus собирает временные ряды
в реальном времени; Grafana отображает их. Ни один из них не заменяет артефакт
эксперимента SQLite. Здесь не нужны центральный сервер и перенаправление SSH
(защищённого удалённого соединения).

```text
Arduino → приёмник :9101 ─────┐
                             ├→ Prometheus на ПК :9092 → Grafana на ПК :3002 → браузер
целевой node_exporter :9100 ──┘
приёмник → основная база SQLite (независима от хранилища панели)
```

## 1. Подготовьте ПО и свой локальный профиль

Установите доступные пакеты ALT на ПК:

```bash
apt-get install prometheus grafana
command -v prometheus grafana-server
```

Сценарий запуска ожидает домашний каталог Grafana `/usr/share/grafana`.
Адаптируйте установку, если ваш пакет использует другую структуру. Порты 9101,
9092 и 3002 должны быть свободны; сейчас порт приёмника фиксирован на 9101.
Одной настройки опроса `receiver-port` недостаточно для изменения порта приёмника.

Используйте скопированный/адаптированный `visionfive2-gpio-local.conf` из
пошаговой процедуры. Сохраните настройки измерения/целевой системы базового
эксперимента. Ключевое отличие:

```ini
[observability]
remote-write-url =
prometheus-port = 9092
prometheus-url = http://127.0.0.1:9092
receiver-port = 9101
grafana-managed = true
grafana-port = 3002
grafana-url = http://127.0.0.1:3002/d/rt-standalone-gpio
```

Сохраните абсолютные пути PID (идентификаторов процессов), журналов, данных и
конфигурации полного профиля и редактируемый `node-exporter-target`. Пустой URL
remote write (удалённой записи метрик) отключает центральную передачу.
`node_exporter` должен работать на целевой системе до сбора. Сценарий запуска
создаёт конфигурацию опроса, источник данных с UID (уникальным идентификатором)
`rt-gpio-prometheus` и файловую настройку панелей из установленных ресурсов;
для нового управляемого экземпляра Grafana ручной импорт автономной панели не нужен.

## 2. Выполните короткую проверку панели

Запускайте из сохранённого каталога эксперимента:

```bash
OBS_SESSION=$(date +%s)
rt-tester-run-gpio --config ./visionfive2-gpio-local.conf \
  --session-id "$OBS_SESSION" --groups 10 \
  --db "$PWD/.rt-tester-example/local-observability.db"
```

Используйте несколько групп: при эталонных настройках группа номинально занимает
около 1.5 секунды, а метрики текущих значений Arduino опрашиваются каждые 500 мс.
Запуск одной группы может завершиться до её попадания в опрос. Скопируйте
напечатанные идентификатор сеанса и URL Grafana.

## 3. Проверьте путь данных во время запуска

Из другого терминала ПК:

```bash
curl -fsS http://127.0.0.1:9101/health
curl -fsS http://127.0.0.1:9101/metrics
curl -fsS http://127.0.0.1:9092/-/ready
curl -fsS http://127.0.0.1:3002/api/health
```

После первой завершённой группы `/metrics` приёмника должен содержать
`arduino_latency_mean`, `arduino_latency_avg` и `arduino_jitter` с `session_id`,
соответствующим запуску. До этого ответ может быть пустым. Приёмник слушает
все интерфейсы ПК; локальный опрос использует петлевой интерфейс.

На `http://127.0.0.1:9092/targets` оба задания во время сбора должны иметь
состояние UP (доступны). Используйте страницу запросов Prometheus или стабильный
HTTP API (программный интерфейс):

```bash
curl -fsSG http://127.0.0.1:9092/api/v1/query \
  --data-urlencode 'query=up{job="arduino_latency"}'
curl -fsSG http://127.0.0.1:9092/api/v1/query \
  --data-urlencode 'query=up{job="runtime_node_exporter"}'
```

Оба значения должны быть `1`, пока точки доступа работают. Запросите
`arduino_latency_avg{session_id="YOUR_SESSION_ID"}` и подтвердите свой сеанс.
После выхода приёмника его `up` становится 0, а текущие значения со временем
исчезают; выберите временной диапазон эксперимента или запросите
`max_over_time(arduino_latency_avg{session_id="YOUR_SESSION_ID"}[1h])`.
`monitor`, `collector` и `stand` — внешние метки удалённой доставки, а не метки
локально опрошенных данных, поэтому не фильтруйте локальные запросы по ним.

## 4. Проверьте Grafana и сохраните данные

Откройте напечатанный URL:

```text
http://127.0.0.1:3002/d/rt-standalone-gpio?var-session_id=YOUR_SESSION_ID
```

Выберите плату `visionfive2`, фактический сеанс и временной диапазон запуска.
Автономная панель показывает задержку хвоста, джиттер (разброс задержек) и
CPU/память целевой системы. «Average» («Среднее») означает среднее худшего хвоста
(наибольших сохранённых задержек); экспортируемое среднее всей группы — другая
метрика. См. [статистику измерений](../reference/measurement-statistics.md).

Если данные есть в Prometheus, но Grafana пуста, проверьте UID источника данных
`rt-gpio-prometheus`, URL `http://127.0.0.1:9092`, переменные/временной диапазон
панели и журналы Grafana. Если порт уже занят неуправляемой Grafana, сценарий
использует её повторно и не настраивает автоматически источник данных/панель;
настройте этот экземпляр явно или остановите перед управляемым примером.

Сохраняйте SQLite, отредактированный профиль, журналы, версии и заметки.
Дополнение CPU/памятью может быть неполным; проверьте покрытие перед сопоставлением
с задержкой. Метрики текущих значений Prometheus описывают последнюю группу,
а не архив всех групп без потерь.

## 5. Остановите управляемый мониторинг

Обработчик измерений удаляется автоматически; мониторинг остаётся доступным.
Из того же каталога эксперимента с тем же профилем:

```bash
rt-tester-run-gpio --config ./visionfive2-gpio-local.conf --stop-observability
```

Это останавливает процессы, указанные PID-файлами профиля. Данные SQLite или
TSDB (базы временных рядов) не стираются, посторонние службы дистрибутива не
останавливаются. Для удалённой доставки метрик переходите к
[центральному мониторингу](central.md).
