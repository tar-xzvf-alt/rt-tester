## Код для ПК

[Код для ПК](https://altlinux.space/besogon1238/rt-tester/src/branch/main/src/pc-receiver)

Код на Python управляет измерениями задержек между Arduino Mega и одноплатником, а также узнает у одноплатнику текущую нагрузку на систему во время получения информации об очередной группе. Он подключается к Arduino через последовательный порт, отправляет команды управления и принимает обработанные данные в формате JSON. Программа работает в интерактивном режиме с консольным управлением.

После запуска код автоматически ищет подключенную Arduino Mega по доступным COM-портам или запрашивает порт вручную. Установив соединение, программа переходит в режим командной строки, где пользователь может управлять измерениями: запускать сбор данных, останавливать сбор и проверять статус.

[Пример конфигурационного файла](https://altlinux.space/besogon1238/rt-tester/src/branch/main/src/pc-receiver/measurement.conf)

Когда Arduino отправляет обработанные данные, скрипт [receiver](https://altlinux.space/besogon1238/rt-tester/src/branch/main/src/pc-receiver/receiver.py) парсит JSON, и сохраняет данные в SQLite базу, из которой может быть выгружена для визуализации отдельным скриптом [plot_statistics](https://altlinux.space/besogon1238/rt-tester/src/branch/main/src/pc-receiver/plot_statistics.py).

Стандартный сценарий использования:


Сбор данных:
```
# связь с Arduino и одноплатником с параметрами указанными в /path/to/params.conf

./receiver.py --params /path/to/params.conf

start # запуск сессии сбора N

stop # остановка сессии сбора N

# повторный вызов 'start' - новая сессия

exit # завершение сбора
```

Анализ данных:

```
# узнать номера сохраненных сессий

./plot_statistics.py arduino_data.db sessions

# узнать средних джиттер в группах сессий N

./plot_statistics.py --session N arduino_data.db jitter

# узнать среднюю задержку для M наихудших задержек в группах сессии N в файл

./plot_statistics.py --session N arduino_data.db --output results/radxa_results/548842_N.png latency 

# узнать информацию о "падениях" стенда во время сессии N

./plot_statistics.py --session N arduino_data.db falls

```



## Код для Arduino

[Код для Arduino](https://altlinux.space/besogon1238/rt-tester/src/branch/main/src/arduino-meter)

Код на Arduino C измеряет задержки в системе связи с SoC. Он отправляет импульсы через пин 7 и принимает ответные сигналы через пин 19. Для каждого импульса измеряется **время отклика системы**(разница между отправкой сигналом на Lichee и получением ответного) и **период между ответными сигналами**.

Программа собирает данные группами: всего 10 групп, в каждой по 500 измерений.

Ардуино работает в циклическом режиме отправки импульсов с фиксированной задержкой 1000 микросекунд между ними. Прерывание по фронту на входном пине фиксирует момент получения ответа от Lichee. По команде START производится сбор данных.

После сбора всех 10 групп программа формирует JSON-пакет со статистикой по каждой группе и общей сводной статистикой, который отправляется на ПК по запросу SEND.

Управление осуществляется через последовательный порт командами START и STOP. Каждая сессия измерений имеет уникальный идентификатор для последующего анализа данных на компьютере.

## Код на платах 

Код на C работает на плате и реализует ответную логику в системе измерений. Программа настраивает два GPIO-пина: один как вход для приема импульсов от Arduino, второй как выход для отправки ответных сигналов.

Код использует библиотеку gpiod для работы с GPIO и ожидает сигнала прерывания SIGINT для корректного завершения. При запуске программа открывает GPIO-контроллер /dev/gpiochipX, конфигурирует пины с соответствующими смещениями в линии GPIO и переходит в цикл ожидания событий.

Основная логика заключается в детектировании переднего фронта на входном пине. Когда Lichee обнаруживает переход сигнала из низкого состояния в высокое (импульс от Arduino), она немедленно устанавливает высокий уровень на выходном пине, формируя ответный импульс. При обнаружении спадающего фронта на входе Lichee сбрасывает выходной сигнал в ноль. Таким образом, код реализует минимальную задержку между получением импульса от Arduino и отправкой ответа, что позволяет измерять время прохождения сигнала в системе. Программа работает непрерывно до получения сигнала прерывания, после чего корректно освобождает все ресурсы GPIO.
